# 后台设计规范

以 Ant Design 设计规范为底（https://ant.design/docs/spec/ ），这里只写它在 `@abysstract/admin-core` 后台里的落地方式和取舍。
框架自带的页面（用户、角色、菜单、字典、日志、首页等）按这一份写；业务模块也按它写。

使用方可以在自己的项目里另写一份补充规范，只写本项目的术语、配色例外和专有组件，不重复这里的规则。两份冲突时以项目那份为准。

写页面前先看这一份；规范没覆盖的情况，先查 antd / Pro 有没有现成做法，再自己决定，并补进来。

## 一、全局样式

### 1. 价值观：取舍和留白

后台页面是给人读的。每个页面先回答“这个人来这里要做什么”，只把完成这件事需要的东西放在第一眼。

- **克制**：能做但不需要的，不做。一个页面突出一件事，其余信息降级（次要色、收进详情、折叠、Tooltip、⋯ 菜单）。
- **行动胜于说明**：不用 Alert、副标题或长提示去解释页面。需要用户去做的事，给一个按钮或链接（例如角色列表里的“分配菜单”）。
  后果提醒只出现在动作发生的那一刻（保存、删除的确认框里），平时不常驻页面。
- **确定性**：重复的规则做成可复用的组件或常量（列表用 `ResourceTable`、筛选用 `ResourceSearchBar`、表单用 `ResourceForm`），不在每个页面各写一套。
  已有的 antd / Pro 组件优先，不重新设计已有的东西。
- **反馈及时**：每个操作都要有结果反馈（`message`、按钮 loading、表格 loading）；不需要额外的文字说明“操作成功后会……”。

### 2. 布局与间距

- **基本单位 8**：间距只用 8 的倍数，并且用 antd token 表达，不写裸像素。

  | 用途 | token | 值 |
  |---|---|---|
  | 同组内元素（图标与文字、标签之间） | `marginXS` | 8 |
  | 控件之间、表单项之间、卡片网格间距；列表的筛选面板与结果面板之间 | `margin` / `Space size="middle"` | 16 |
  | 区块之间（详情的两个分组） | `marginLG` | 24 |
  | 页面级大分隔（很少用） | `marginXL` | 32 |

  需要 4 的场合（紧凑标签内）用 `marginXXS`。不要出现 6、10、12 这类不在刻度上的间距。
- **栅格 24 列，间距固定 16**：用 antd `Row gutter={16}` + `Col span`。窗口变宽时列变宽、间距不变。
- **适配屏幕**：设计按 1440 宽，必须在 1366 和 1920 下都正常；1280 下不出现横向滚动（表格除外，用 `scroll.x`）。
  左侧菜单固定，右侧内容区随宽度伸缩（框架的侧边布局即如此）。
- **抽屉宽度**：只用两档。表单、详情 `720`（单列阅读最舒服的宽度），需要并排两栏的复杂编辑 `1000`。
- **表单字段宽度**：在抽屉或页面表单里用栅格，三档：
  短值（数字、是/否、短编码）`span 6`，名称、单选、多选 `span 12`，长文本 `span 24`。
  同一行的字段高度对齐；长文本不和短字段挤在同一行。
  **只有彼此相关的字段才并排**（用户名与昵称、手机号与邮箱、字典标签与键值）；无关的字段即使宽度只有一半也另起一行，行尾留空。

### 3. 字体

- 字体用 antd 默认的系统字体栈，不另引字体。
- **基础字号 14、行高 22**。一个页面只用 3 种字号：
  - 14：正文、表格、表单（默认，不用设置）；
  - 12：辅助说明、表格里的次要行（`Typography.Text type="secondary"` 配 `fontSizeSM`）；
  - 16：页面内分组标题（`Typography.Title level={5}` 或 Card 标题）。
  页面标题由 `PageContainer` 负责。需要强调时跳级（14 → 16 以上），不要用 13、15 这类相邻字号做区别。
- **字重**：正文 400；强调只用 `Typography.Text strong` 或标题组件自带的字重（antd 的 `fontWeightStrong`），
  不自己写 `fontWeight`。一个区域里加粗的只有一处（通常是名称）。
- **数字**：需要上下对齐比较的数字列（数量、排序号、耗时）加 `font-variant-numeric: tabular-nums`，并右对齐。
- **编码**（权限标识、字典类型、路由路径）用次要色显示，不用等宽字体，除非需要逐字符核对（如密钥前缀、请求 ID）。

### 4. 颜色

- **主色**用 antd 默认的 `#1677ff`，框架不在 `theme` 里覆盖。使用方要换品牌色时，在传给框架的 `ConfigProvider` 主题里改 `colorPrimary`，并确认按钮上的白字看得清。
  主色只用于主要操作按钮、链接、选中状态。一个区域只有一个主按钮。
- **功能色**只表达状态，不做装饰：
  成功 `success`（绿）、警告 `warning`（橙）、错误 `error`（红）、信息/进行中 `processing`（蓝）。
  `Tag` 的颜色同样只表达状态或一个确有意义的分类；普通分类（菜单类型的目录、菜单、按钮，通知类型的通知、公告）用默认灰色 Tag。
- **中性色**全部用 token，不写十六进制：
  正文 `colorText`、次要 `colorTextSecondary`、禁用/占位 `colorTextQuaternary`（`colorTextDisabled`）、
  边框 `colorBorder`、分割线 `colorSplit`、浅底 `colorFillTertiary` / `colorBgLayout`。
  在组件里通过 `theme.useToken()` 取值。
- **空值**统一显示次要色的 `-`（与 ProTable / ProDescriptions 默认一致，见第二部分「数据格式」）；整组都为空时不显示这一组，而不是一排 `-`。

### 5. 阴影与层级

用 antd 组件自带的阴影，不自定义 `box-shadow`。

- 0 级（不浮起）：输入框、表格、页面内的卡片（包括列表的筛选面板和结果面板）。页面内卡片用边框或留白区分，不加阴影。
- 1 级（交互时浮起）：可点击卡片的悬停（`Card hoverable`）。
- 2 级（依附于触发元素）：下拉菜单、Popover、Tooltip。
- 3 级（独立浮层）：Modal、Drawer、message。

### 6. 图标

- 用 `@ant-design/icons` 的 **Outlined** 风格，全站统一，不混用 Filled / TwoTone（状态图标除外，如 Result）。
- 图标跟随文字字号和颜色，不单独设大小（空状态、占位图除外）。
- **能用文字就用文字**：表格操作列用文字链接（编辑、删除）。只有含义无歧义的通用动作才用纯图标，并且必须有 `aria-label`，
  最好配 Tooltip：更多（⋯）、上移、下移、删除（在列表项内）、刷新。
- 不在标题、菜单、按钮里为了装饰加图标。

### 7. 暗色模式

框架目前不提供暗色主题切换。为了将来能直接切换：颜色一律走 token、不写死十六进制；图片占位背景用 `colorFillTertiary` 而不是 `#f5f5f5`。

## 二、设计模式

以 Ant Design「设计模式」为底（https://ant.design/docs/spec/overview-cn ）。先用现成的页面模板和组件，
只有业务确实特殊时才自己组合。

### 1. 页面类型

后台页面分三种，每种页面的任务和布局固定：

| 类型 | 任务 | 例子 | 布局 |
|---|---|---|---|
| 列表页 | 找到要处理的那一条 | 用户、角色、菜单、字典、操作日志、请求日志 | 标题 + 筛选面板 + 结果面板（右上角页面操作）+ 表格 + 分页 |
| 详情 | 读懂一条记录 | 请求日志详情、字典数据 | 最重要的内容在第一屏；次要信息折叠或放后面 |
| 编辑 | 改一条记录 | 新增用户、编辑角色、个人中心 | 抽屉或弹窗里的表单，分组、栅格对齐 |

一个常用任务最多跳转一到两次页面。

### 2. 反馈

| 场景 | 用什么 | 不用什么 |
|---|---|---|
| 操作成功、不重要的结果（已保存、已删除、没有变化） | `message`，约 3 秒自动消失 | 弹窗 |
| 需要用户决定的危险操作（删除、清空日志、重置密码） | 删除单行用 `Popconfirm`；影响大、需要说清后果的用 `Modal.confirm` | 事后提示 |
| 重要失败、用户必须处理（无法删除：被引用） | `Modal.error`，写清原因和下一步 | 一闪而过的 `message` |
| 表单字段错误 | 字段下方的校验信息，改正前一直显示 | 顶部 Alert |
| 加载 | 表格、按钮自带的 `loading`；首屏无内容时用 `Skeleton` | 整页遮罩 |
| 页面级、持续有效的状态（如请求日志未开启） | 页面顶部 `Alert` | — |

- `Alert` 只用于**持续有效、需要一直看到**的状态，不用来解释页面或功能。说明性的文字一律删掉，或者改成按钮。
- `Tooltip` 只解释它指向的那个东西，一句话，不放操作；需要放链接、按钮时用 `Popover`。
- 一看就知道结果的简单操作（切换视图、展开折叠）不额外提示。

### 3. 导航

- 侧边菜单最多三级（如 系统管理 → 用户管理）。菜单名 2 到 6 个字。
- 详情页用 `PageContainer` 的返回箭头回到列表；不另加面包屑。
- 从详情返回列表时，**筛选、分页、滚动位置都保持**。列表的关键词、筛选、页码、每页条数和排序都写在地址栏里（`ResourceTable` 默认如此），刷新、后退、分享链接、在新标签页打开都回到同一画面。地址只写与默认值不同的部分，参数名用字段名，保持可读。
- 不做应用内多标签页，同时看几条记录用浏览器标签页。所以每个页面都要有自己的地址：需要单独打开的详情页声明为隐藏菜单（模块 seed 中 `"hidden": true`，有路由和权限检查，不进侧边栏），路径可以带参数，如 `detail/:code`。
- 打开另一个页面的入口一律是真正的链接（`<a href>`），中键、Ctrl/⌘ 点击和右键“在新标签页中打开”都能用：页面里用 react-router 的 `<Link to>`，表格行操作用自定义操作的 `href`。不要用 `onClick` 里调 `navigate()` 的按钮代替链接。
- 同一页面的几类平行内容用 `Tabs`，标签名 2 到 6 个字。
- 分页：只有一页时隐藏分页器；超过 5 页时显示快速跳转。页大小可选，默认值按内容定（表格 20，卡片网格 24）。

### 4. 数据录入（表单）

- **标签放在输入框上方**（`layout="vertical"`），全站统一。表单都在抽屉或弹窗里，宽度有限，上方标签更省空间、更好扫读。
- 字段排布按第一部分的栅格规则：短值 1/4，名称、编码、下拉 1/2，长文本整行；按用途分组，每组一个小标题。
- 必填用 antd 自带的红色星号，不另写“必填”。
- **说明文字**：短的放在字段下方（`extra`），长的放在标签旁的问号图标（`tooltip`）。不在表单顶部放 Alert 讲规则。
  只写用户需要知道的约束（“创建后不能修改”），不写系统怎么实现。
- **校验**：提交时整体校验；格式类错误在失去焦点时提示。错误写在字段下方，说清该怎么填。
- **控件选择**：
  - 少于 5 个选项、且需要一眼看全时用 `Radio`；5 个及以上或可搜索时用 `Select`；
  - 多选用 `Select mode="multiple"`，选项多时可搜索；
  - `Switch` 表示**立即生效**的开关（如列表里直接启用/停用用户）。随表单一起保存的开关用 `Checkbox`，
    三态（是/否/未填写）用可清空的 `Select` 或 `Radio`；
  - 长文本用 `Input.TextArea` 并设 `autoSize`，不固定行数。
- 有合理默认值的字段直接预填（例如在字典数据抽屉里新增，字典类型预填为当前字典）。
- **占位文字不重复标签**：标签已是“用户名”，就不写“请输入用户名”；有格式要求时写示例，比如“system:user:list”。

### 5. 数据列表

- **表格还是卡片网格**：需要逐列比较的用表格；以图片识别为主的用卡片网格。
  表格列只放用来**找到和区分**这一条记录的字段，其余进详情。经验上一张表不超过 7 列（不含图片和操作）。
- **筛选栏和结果分成上下两块面板**，即框架 `ResourceTable` 的布局。筛选栏用 `ResourceSearchBar`。
  - 筛选栏从左到右：关键词框 → 筛选下拉 → **查询**（主按钮）→ **刷新**。不放“重置”：
    下拉都可单独清空，筛选后没有结果时空状态里有“清除筛选”。
    下拉、复选框、日期改了立即生效；关键词点“查询”或回车生效，删空时立即生效；“刷新”按当前条件重新加载。
    只用占位文字，不加标签。条件多时只露出最常用的几个，其余收进“更多筛选”。
  - 结果面板右上角放页面操作（“新增”、视图切换）；没有筛选的页面把“刷新”也放在这里。
  - 没有对应权限的操作按钮直接不显示，不显示成禁用。
- **打开详情**：点名称打开。内容一屏以内用展开行，超过一屏用抽屉，需要分享链接或任务复杂时用独立页面。
- **操作列**：最多两个文字链接（最常用的，如“编辑”），其余收进最右边的“⋯”。点名称已能打开详情时，不再放“查看”。
  例如用户列表：“编辑”“⋯”（重置密码、删除）。
- **新增**：右上角主按钮“新增”，打开抽屉或弹窗；保存后新记录出现在列表里。
- **删除**：必须确认；确认文案写清后果。
- **批量操作**：选中行后在表格底部出现操作条，不放在顶部工具栏里和页面操作混在一起。
- **时间、状态、操作列**不换行；编码、名称过长时省略并用 Tooltip 显示全文。
- **空状态**：没有数据时说明为什么空、可以做什么（例如“没有符合条件的用户”+“清除筛选”），不只写“暂无数据”。见第五部分「空状态」。

### 6. 按钮

- **默认按钮是最安全的选择**。主按钮（`type="primary"`）一个区域最多一个，只给完成任务的那个动作（保存、新增）。
- 表格操作列、密集区域用文字链接（`type="link"`，`size="small"`）。
- 危险操作（删除）用 `danger`，并放在同组最后。
- **顺序**：推荐的操作在前，危险的在后；返回、上一步在最左。工具栏里：业务操作 → 视图切换 → 其他 → “⋯”。
  抽屉、弹窗的按钮在右上（抽屉 `extra`）或右下（弹窗 footer），顺序为“取消 保存”。
- 按钮太多时，次要操作收进最右边的“⋯”下拉菜单。
- 一个按钮最多一个图标；纯图标按钮必须有 Tooltip 和 `aria-label`。
- **文案**用动词、简短，说明结果：“保存”“删除”“重置密码”，不用“确定”泛指。删除确认用“删除 / 取消”。新建记录统一叫“新增”。

### 7. 文案

- **称呼用“你”**，不用“您”；同一句里不混用“你”和“我”。
- 不用命令式的“请勿”“不能”开头；说明能做什么、该怎么做。
- **出错不怪用户**：用“无法……”而不是“失败”，并说明下一步（“无法删除：有 3 个用户属于这个角色。先移除这些用户的角色。”）。
- **精简**：不重复用户已经知道的信息，不写“成功”二字（“已保存”而不是“保存成功”）。
- **标点**：按钮、标题、标签、Tooltip、表格单元格里的短句不加句号；多句说明才加。
  中文与数字、英文之间加空格：“共 24 条”“3 个角色”“IP 地址”。括号用全角：“耗时（ms）”。省略号用“…”。
- **术语统一**：同一个概念在界面上只用一个词。项目自己的术语表写在项目的补充规范里。

### 8. 数据格式

- **日期时间**：`YYYY-MM-DD HH:mm:ss`，24 小时制；只需要日期时用 `YYYY-MM-DD`。
  不用 `toLocaleString()`（格式随浏览器语言变化）。日期范围用“ ~ ”连接。后台列表一律显示绝对时间，不用“3 分钟前”。
- **数字**：千分位分隔（`123,220`）；数量、排序号、耗时等数字列右对齐；单位写在列标题里，不写在每个单元格。
- **百分比**：`12.32%`；进度或比例：`12/30`。
- **空值**：`-`（次要色）。
- **敏感信息**：密钥只显示前缀，后面用 `…`；不显示完整值。

### 9. 数据展示（详情）

- 内容按**重要性、使用频率、相关性**排序：一条记录最核心的 3 到 5 项放在第一屏最显眼的位置
  （如请求日志的接口、结果、耗时、用户、时间）。
- 内部字段（ID、请求 ID、排序号、创建人）不和业务字段放在同一层级：收进折叠区或“更多信息”。
- 长而不常看的内容（请求参数、响应内容）用 `Collapse` 折叠；彼此无关的几块可以用手风琴（一次只展开一块）。
- 分组用 `Card` 或带小标题的区块，一行最多 4 张卡片；卡片之间留足间距，长文本截断。
- 详情里的空字段不显示；整组都空时整组不显示。


## 三、设计原则

Ant Design 的十条原则（https://ant.design/docs/spec/proximity-cn 等）。这里只写它们在框架里的具体做法。

### 1. 亲密性：越相关，越靠近

- 垂直间距只用三档：同一组内 8，组与组之间 16，区块之间 24（公式 `8 + 8n`）。三档不够时再加 8 的倍数，或用分割线，而不是自创间距。
- 字段的标签、输入框、说明是一组，彼此 8；字段与字段之间 16；表单分组之间 24。
- 列表里，名称和它的编码靠在一起（例如用户名后面跟次要色的昵称）；操作和内容分开。

### 2. 对齐：一条起始线

- 标题、正文、表单标签统一左对齐，一个区域只有一条起始线。
- 数字右对齐，同一列保留相同的小数位。
- 表单标签放在上方（见第二部分「数据录入」），所以不涉及冒号对齐。如果某个表单改用左侧标签，标签右对齐、冒号对齐成一条线。

### 3. 对比：要强烈，不要畏畏缩缩

- 主次操作：一个区域只突出一个主操作，其余用默认按钮或文字链接；也可以通过弱化其他项来突出它。
- **中立决策不诱导**：需要用户慎重判断、两个选项没有对错之分时（例如“通过 / 驳回”），两个按钮都用默认样式。
- 层级：名称用正文色并加粗，编码、时间等用次要色、小一号，形成明确的主次，而不是所有字段同样醒目。
- 状态：用颜色点或 Tag 表示；悬停时给出明显变化（Table 行悬停、`Card hoverable`）。

### 4. 重复：同一件事永远一个样子

- 同一类信息在所有页面用同一种表现：空值都是 `-`，时间都是同一格式，编码都是次要色。
- 同一类页面用同一种结构（第二部分「页面类型」）；同一类操作在同一个位置（新增永远在右上，更多永远在最右的“⋯”）。
- 发现两个页面写法不同时，抽成共用组件，而不是各改各的。

### 5. 直截了当：在哪里看，就在哪里改

- 编辑尽量不离开当前页：用抽屉或弹窗，不跳到另一个页面。
- 单个字段、改动频繁且没有副作用的（例如菜单的排序号），可以考虑行内编辑：悬停显示编辑图标，点击后出现输入框和确认、取消。
  影响范围大的修改（例如角色的菜单权限），仍然走表单和确认，不做行内编辑。
- 调整顺序目前用上移、下移按钮；以后改成拖拽时，只允许沿一个方向拖，并给出可放置位置的提示。

### 6. 足不出户：尽量在当前页完成

- 详情、编辑优先用抽屉；只有需要分享链接或任务复杂时才用独立页面。
- 平行内容用 Tabs，一次显示一组。
- 删除：Ant Design 推荐“直接删除 + 撤销”。数据删除后通常无法恢复时，**保留确认**，用 `Popconfirm` 或 `Modal.confirm`。
- 不为了确认而弹窗：只有不可逆或影响范围大的操作才确认。

### 7. 简化交互：操作放在内容旁边

- 重要操作一直可见；次要操作在悬停或进入某个模式时才出现，不常驻干扰阅读。
- 点击区域要大：整张卡片可点，表格里点名称所在的整格，而不是只有几个字的链接。
- 鼠标悬停时光标变成手形、背景变化，提示可以点。

### 8. 提供邀请：让可做的事被发现

- 不显眼的交互（行内编辑、拖拽、悬停操作）要有提示：悬停时出现图标或链接。
- 空状态、未完成状态是邀请：告诉用户下一步可以做什么，并给按钮（“新增字典”“清除筛选”）。
- 不用新手引导来弥补设计问题。

### 9. 巧用过渡：说明刚刚发生了什么

- 新增后，新记录出现在列表中并短暂高亮，几秒后恢复。
- 保存修改后，详情或列表里变化的那一条短暂高亮。
- 删除后，该行移除（表格自带动画即可）。
- 只用 antd 组件自带的动画，不自己写动画。

### 10. 即时反应：每个操作都有回应

- 反馈的强弱与操作的分量相当：切换筛选 → 表格 loading；保存 → 按钮 loading + `message`；删除失败 → 弹窗说明原因。
- 筛选条件改变后立即刷新结果；关键词搜索在回车或停止输入后刷新。
- 提示只在需要的时候出现（渐进展示），不预先铺满页面。
- 超过约 2 秒的操作显示进度；很长的操作提供取消。


## 四、页面模板

第二部分定了三种页面类型，这里补充两种模板：详情页和数据概览页。

### 1. 详情页

目标：读得快、找得到、改得方便。

- **平铺优先**：业务字段直接展开，不为了“整洁”而折叠。只有内部字段（ID、请求 ID、排序号、创建人）收进“更多信息”，这是对第二部分第 9 条的限定：折叠只用于不常看的内容，不用来藏业务信息。
- **按复杂度选布局**，能用简单的就不用复杂的：

  | 布局 | 什么时候用 | 例子 |
  |---|---|---|
  | 基础详情 | 信息少、彼此相关 | 请求日志详情：一个区域，组与组之间用不通栏 `Divider`（或带小标题的区块）分开，不每组套一张卡片 |
  | 单据详情 | 需要判断并处理（通过、驳回） | 审批类业务：内容和处理操作各占一块，操作放在内容之后，两个按钮都用默认样式 |
  | 高级详情 | 信息多、相关性弱，必须分页签 | 一个对象超过三组无关信息时再考虑 `Tabs` |

- **分隔手段由轻到重**：留白 → 不通栏分割线（组内分开）→ 通栏分割线（分成几部分）→ 卡片（一个主题）→ 页签（最顶层）。用能分清的最轻那一种。
- **同类结构**：所有详情的字段区都用 `Descriptions`。在 720 抽屉里 2 列，在整页里 3 列；标签用默认样式，不加粗、不加冒号以外的符号。
- **操作位置**：编辑、删除等对象级操作放在标题右侧（抽屉 `extra` 或 `PageContainer` 的 `extra`），不散落在内容中间。

### 2. 数据概览页

框架首页（用户数、角色数、今日登录、最近登录）和业务的概览页按这里来：

- **先结论，后细节**：最重要的数字放在左上方。分析路径是“概览 → 筛选 → 明细”，数字可以点进对应的已筛选列表（今日登录 → 登录日志），不另做明细页。
- **数字优先于图表**：一个数就能说清的，用 `Statistic` 指标卡，不画图。只有看趋势或分布时才用图表。
- **数量克制**：一屏 5 到 9 个模块。一张卡片只讲一件事；相关性高的几个数可以放在同一张卡片里，用通栏分割线隔开。
- **指标卡**：栅格上用 `quarter`（一行 4 个）；重要性接近时等宽平铺，需要突出一个时它占 `half`。
- **颜色**：图表配色用 AntV 默认色板，不自己配色；功能色仍只表示状态（例如失败数用红色）。
- **定义**：口径不直观的数字（如“在线”）在标题旁放 `Tooltip` 说明，不在页面上写段落。
- 某一块没有数据或加载出错时，按第五部分的空状态和异常处理，不隐藏整块，也不显示成 0。


## 五、状态与反馈

补充第二部分的反馈和数据列表，冲突时以本节为准。

### 1. 异常与状态

每个页面和每个区块，都要考虑这五种状态：

| 状态 | 怎么做 |
|---|---|
| 正常 | — |
| 部分为空 | 空的字段或分组不显示（见第二部分第 9 条） |
| 加载中 | 表格、列表用组件自带 `loading`；详情首屏用 `Skeleton`；不用全屏遮罩 |
| 出错 | 区块内用 `Result` 或一行错误说明，并给“重试”按钮；不只弹一个 message 就留下空白页 |
| 全空 | 引导式空状态：为什么空，加一个可点的下一步（见下面「空状态」） |

- **整页异常**用 antd `Result`，写清三件事：发生了什么、为什么（可选）、下一步按钮。
  - 404：打开的记录已被删除，或者地址不存在。提示后给“返回列表”。
  - 403：没有权限。说明需要什么权限，不给无效按钮。
  - 500 或网络错误：说明无法加载，并给“重试”。
- 文案说人话，不出现 `ConnectError`、`not_found` 这类原文；错误代码只放在详情里，方便反馈。

### 2. 空状态

空状态分三种，先判断是哪一种再写文案：

| 类型 | 什么时候 | 怎么做 | 例子 |
|---|---|---|---|
| 第一次使用 | 这里从来没有过数据 | 一句话说明这里放什么，加一个创建按钮 | 字典为空：“还没有字典” +「新增字典」 |
| 处理完了 | 用户把事情做完了 | 只说结果，不给按钮 | 首页待办全部处理完：“没有待处理的事项” |
| 没有结果 | 有数据，但被条件挡住了 | 说明原因，给一个解除条件的操作 | 筛选无结果：“没有符合条件的用户” +「清除筛选」 |

- 一律用 antd `Empty`。页面级用默认插图，表格、区块、抽屉内用 `Empty.PRESENTED_IMAGE_SIMPLE`。不自己画插图。
- 不写“暂无数据”这种不说原因的文案。
- 单个字段为空显示 `-`，不算空状态。

### 3. 消息与反馈

按两件事选组件：结果是成功还是失败，用户要不要停下来处理。

| 场景 | 用什么 |
|---|---|
| 成功，留在原地（保存、删除、复制） | `message.success`，一句话，不打断 |
| 输入不符合要求 | 表单校验，错误写在字段下方，抽屉不关闭 |
| 提交失败，原因用户能处理（用户名重复、数据已被他人修改） | 抽屉不关，能对应到字段的标在字段上；否则用 `message.error` 写原因和下一步 |
| 提交失败，原因用户处理不了（服务出错） | `message.error`：“无法保存，请稍后重试”，表单内容保留 |
| 需要先停下来再做决定（删除、清空日志） | 操作前用 `Modal.confirm` 或 `Popconfirm`，写清后果 |
| 页面上持续存在的状态（请求日志未开启、只读） | 页面顶部 `Alert`，状态解除后消失 |
| 后台任务的结果（批量导入） | `notification`，带“查看”链接 |

- 失败后不清空用户填的内容。
- 成功不用 Modal 庆祝，也不跳结果页。


## 六、给 AI 用的资料

本规范只写框架自己的取舍；组件 API、Token 默认值以 Ant Design 官方资料为准。
antd 版本跟着 `@abysstract/admin-core` 的 peer 依赖走（见本包 `package.json` 的 `peerDependencies.antd`，当前是 antd 6），查资料时按 v6 查，不用已废弃的 v5 写法。

| 资料 | 用途 | 怎么用 |
|---|---|---|
| `@ant-design/cli`（`antd` 命令） | 离线查组件 Props、Demo、Token；`antd lint` 检查废弃 API | **主要工具**。改页面前用 `antd info <组件> --version <项目里的 antd 版本>` 查 API，改完跑 `antd lint ./src` |
| 单组件文档 `https://ant.design/components/<name>-cn.md` | CLI 不可用时查单个组件 | 按需查一个组件，不整份读取 |
| `llms-full-cn.txt` | 全部组件文档 | 不用，太大，按需查单个组件就够了 |
| 官方 `design.md` | 给 Stitch、Figma Make 这类设计工具的默认主题说明 | 不另外引用；框架用默认主题，这里的规范已覆盖要用的部分 |
| MCP Server（`antd mcp`） | 在 IDE 里以工具形式提供上面的查询 | 可选；命令行已能做同样的事 |
