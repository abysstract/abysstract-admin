# Resource 与专用业务流程

开发业务功能时，按操作特点选择 Resource、Hook、Repository 或专用接口。字段与事务规则统一见 [Resource 手册](ai-cookbook.md)，接入步骤见[模块教程](new-module-tutorial.md)。

## 选择扩展位置

| 需求 | 扩展方式 |
|---|---|
| 普通字段、筛选、排序和可写规则 | Resource 声明 |
| 写入前的业务校验、规范化和同事务事件 | Hook |
| 提交后的通知或缓存失效 | `AfterCommit*` 回调 |
| 特殊查询、软删除或缓存包装 | 注入 Repository，沿用当前事务和数据范围 |
| 密码、授权关系、多表业务动作和文件处理 | 专用接口或服务 |
| 特殊展示、表单组件和业务按钮 | 页面 Overrides |

注入 Repository 时，可以委托生成的标准方法，只为有业务差异的操作提供实现。方法列表见[公共 API 用法](admin-core-usage.md#数据访问与回调)。

## 系统功能示例

自带系统功能展示了这些扩展方式的适用场景：

| 功能 | 需要处理的业务规则 |
|---|---|
| 字典、参数 | 值校验、关联选项和提交后缓存失效 |
| 公告 | 类型、状态和内容校验 |
| 部门、菜单 | 树形关系、子节点保护及关联清理 |
| 用户、角色 | 密码、状态、数据范围、授权关系及内置账号保护 |
| 登录、个人资料、上传、日志 | 按业务操作定义接口 |

业务模块可以参考这些场景选择扩展方式。普通 CRUD 页面使用生成的 schema、operations 和 `ResourceTable` / `ResourceForm`，需要特殊交互时添加 Overrides。
